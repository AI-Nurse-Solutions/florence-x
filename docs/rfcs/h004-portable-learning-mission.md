# Draft RFC H-004 / Speed Sprint SS-01: portable learning mission

Status: proposed engineering, not policy or deployment authorization.
Base: Florence-X 369bac4171cdd001dd9b20e16b18cb9b9e33d0bd (draft PR #17).

## Human need and acceptance (specified before execution)
A nurse should keep the same learning goal and inspectable professional record
when the model, runtime or hosting arrangement changes. The first visible slice
is a synthetic, goal-identified mission with three architecture previews.

1. Open the same goal on desktop and 390px mobile viewports.
2. Preserve the mission ID, goal and canonical digest across all three previews.
3. Describe interaction, harness, authoritative-storage and inference placement
   separately. Show actual browser-only preview separately from those targets.
4. Reject unsupported profiles, unknown/nonpublic classifications, mismatched
   fixture endpoint references, extra executable fields and attempted activation.
5. Make no inference, upload, portfolio write or privileged runtime call.
6. Retain every baseline source file, existing schema and held file unchanged.

Primary pillar: Capability. Dependencies: Knowledge (source and limitation
records), Judgment (an understandable choice without automatic action),
Contribution (stable attributable records). Potential harm: architecture machinery
could displace learning value; metadata could be mistaken for authorization.
Evaluate the visible mission, not only schema coverage. Human evaluation pending.

## Source/code findings and authority
The September 2026 project design outline calls for stable responsibilities,
separate permission, and a public-source first mission. Both supplied IoC drafts
remain distinct draft sources; this RFC does not ratify or reconcile their
philosophical or tier differences. The repository's CLAUDE.md, BUILD_PLAN.md and
EDENA integration contract were inspected. Their broader institutional examples
are not permission to admit clinical data to this personal preview.

The H-003 catalog already defines CatalogRecord, CatalogSource and shared value
types. Reuse those in schemas/mission.py, rather than create another source model
or change any existing schema. MissionRecord is a draft learning document, NOT a
WorkflowRun, ActionIntent, ApprovalRecord or ExecutionReceipt. No invented success
receipt, professional credential or execution authority appears in it.

## Minimal architecture
Mission identity, goal, source references and limits live in MissionRecord.
DeploymentManifest describes target placements separately; it cannot activate a
runtime. The bundle carries exactly one local, hybrid and hosted-test manifest.
Endpoints are fixed inert fixture references, not usable URLs. All enable flags
are strict booleans and must be false. Hermes is optional and not connected.

The self-contained companion web shell renders validated bundled records. It
uses no remote libraries, storage API, file upload or model API. A deployment
comparison changes only the view. Its temporary pause control pauses inspection,
not a background job. Reload clears view state. Inspectable JSON is not a saved
portfolio. A generated snapshot is derived, not a second canonical source.

No raw Hermes state or provider conversation ID owns mission identity. Actual
adapters, authentication, durable records and migrations remain later increments.

## Validation and limitations
The core reuses Pydantic's existing project dependency. It rejects unknown fields,
duplicate JSON keys, non-finite constants, oversized JSON and inconsistent target
placements. Copied model instances are revalidated. Exported errors are generic.
Classification is a declaration: these checks are NOT a privacy classifier,
semantic evidence validator or sandbox against arbitrary same-process code.
A content digest proves comparison integrity only, not authorship or truth.

The prototype has no free-text or file entry. The source pack is empty and labeled
not yet loaded. Do not replace this with invented evidence to make the screen look
complete. Formal decision, generation, persistence and sharing remain unavailable.
Browser rendering is not professional review, accessibility certification or proof
of understanding. A hosted-test manifest is not a hosted service.
